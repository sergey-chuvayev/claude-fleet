# React migration: test map for the browser-coupled tests

Date: 2026-10-06. Work package 1 of `docs/plans/2026-10-06-react-migration-design.md` (section 12). Baseline: `origin/react-migration` at `ee63d5e`, package 0.54.0.

Section 11 of the plan says each removed test has a mapped replacement or a documented obsolete invariant. This is that map. A "browser-coupled" test is one that loads `public/*.js` or `public/index.html` into a `vm` context with a stub DOM, requires a `public/` module, or reads its source text. Acceptance rows A01 to A33 are in section 11; A30 to A33 were added by this work package for the features that arrived after the plan (F29 to F35).

Rules for using the map:

- A legacy test is deleted only when its replacement exists and passes in the same PR (plan section 12, package 6).
- "Port" means keep the assertions, change only the harness (the function is pure and survives as a TypeScript module). "Rewrite" means the invariant stays and the test is rewritten as a Testing Library interaction or a Playwright journey. "Obsolete" means the invariant exists only because of the IIFE architecture; the reason is given.
- Rows that name a new React test give the file the test should live in under `frontend/src/`.

## Tests that are not browser-coupled and stay

Everything else in `*.test.js` runs against Node modules or `createApp` over HTTP and does not load `public/`. These are the contract and domain tests the plan retains (section 11): `managed`, `day*`, `projects`, `progress`, `pr-status`, `checkouts`, `permissions`, `search`, `settings`, `archive`, `connections`, `usage`, `service`, `open`, `paths`, `history`, `references`, `dispatch`, `worktree`, `owner-review`, `team-store`, `teams`, `tasks`, `routing`, `theme`, `sync` (server halves), `codex*`, and the package-content tests in `package.test.js`.

## Fixture coverage

Each F identifier has fixture evidence in `frontend/src/test/fixtures/` (see the README there for the F to pack map). Behaviors that cannot be captured from the server (timing, network failure, DOM-only state) are the scripted scenarios in `failure-lifecycle/scenarios.json` and the Playwright journeys.
